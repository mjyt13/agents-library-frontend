# CS2 Agents Library — план и текущая архитектура

## Текущее состояние

Проект сейчас устроен вокруг фракций, подфракций, агентов и голосовых линий.

- `Faction` содержит `id`, `name` и массив `subfractions`.
- `Subfraction` разделена на статическую мету и ленивый источник аудио.
- `SubfractionMeta` содержит `id`, `name`, `agents`.
- `SubfractionAudioSource` содержит `voicePages` и `loadVoicePage(pageId)`.
- `voicePages` считаются частью аудио-источника, потому что они строятся из доступных аудиофайлов.
- Основная страница подфракции — [SubfractionPage.vue](src/pages/SubfractionPage.vue).
- Общая страница фракции — [FactionPage.vue](src/pages/FactionPage.vue).
- Звуковые группы отображаются через [AudioContent.vue](src/widgets/AudioContent.vue).

Маршруты уже разведены по фракциям через `views`, а фракционные страницы в основном используют общий `FactionPage`.

## Недавно реализовано

- **Картинки → WebP пайплайн.** Все png/jpg/jpeg в `src/interface/data` сконвертированы в WebP (74 MB → ~9.8 MB). Скрипт [scripts/compress-images.mjs](scripts/compress-images.mjs) (`npm run compress:images`) на `sharp`: ресайз до 1600px, q80, конвертация + пере-сжатие крупных webp. На сборке — `ViteImageOptimizer` ([vite.config.ts](vite.config.ts)) даёт ещё ~−35% без правки исходников. Строковые `photos` агентов переписаны на `.webp`; попутно починены 2 битые ссылки (`ricksaw`, `rouchard`).
- **Реестр фракций.** [src/interface/data/factions/index.ts](src/interface/data/factions/index.ts) — единый массив `factions` для `pickRandom` и будущей централизации импортов.
- **Случайный звук на главной.** [getRandomAudio.ts](src/utils/getRandomAudio.ts) идёт по цепочке резолва и отдаёт случайную реплику из заданных групп; кнопка на главной с debounce (leading-edge) и предзагрузкой первого звука в `onMounted`.
- **Единый источник id категорий.** [voiceCategories.ts](src/utils/voiceCategories.ts) (`voiceCategory` как `as const` + тип `VoiceCategoryId`); `buildVoicePages` переведён на него.
- **Фон-видео на главной.** `<video>` во всю высоту (`object-fit: cover`) + картинка-плейсхолдер до `loadeddata`.

## Данные

Основная структура данных:

```ts
interface Faction {
  id: string
  name: string
  subfractions: Subfraction[]
}

interface SubfractionMeta {
  id: string
  name: SubfractionType
  agents: Agent[]
}

interface Subfraction {
  meta: SubfractionMeta
  loadAudioSource: () => Promise<SubfractionAudioSource>
}

interface SubfractionAudioSource {
  voicePages: VoicePageMeta[]
  loadVoicePage: (pageId: VoicePageId) => Promise<AudioContent[]>
}
```

Подфракции сейчас лучше держать в таком виде:

```text
factions/<faction>/<subfraction>/
  audio/
  meta.ts      // id, name, agents
  audio.ts     // import.meta.glob по аудио этой подфракции
  male.ts      // тонкий экспорт Subfraction
```

Пример:

```ts
export const professionals_fem: Subfraction = {
  meta,
  loadAudioSource: () => import('./audio').then((module) => module.audioSource),
}
```

Так основной модуль подфракции не тянет аудио-манифест сразу. Аудио-группы и страницы создаются только при загрузке `audio.ts`.

## Аудио

Аудио оптимизация на текущем этапе завершена.

- Аудиофайлы остаются в `src/interface/data`, переход в `public` пока не нужен.
- `import.meta.glob` используется локально в `audio.ts` каждой подфракции.
- Широкий `audioAssets = import.meta.glob('/src/interface/data/**/*.{wav,ogg,oga}')` из `SubfractionPage.vue` убран.
- `createAudioContentFromFiles` превращает имена файлов в `AudioContent[]`.
- `buildVoicePages` раскладывает группы по смысловым страницам и объединяет разные названия в общие категории.
- `createAudioSourceFromModules` собирает `SubfractionAudioSource` из локального `import.meta.glob`.
- `SubfractionPage.vue` лениво вызывает `loadAudioSource()`, кеширует audio source и отдельно кеширует страницы.
- `AudioContent.vue` лениво резолвит конкретные аудиоэлементы при раскрытии дропдауна.

Важно: `voicePages` не стоит хранить в `meta.ts`, если они строятся по аудиофайлам. Это аудио-метаданные, а не статическая мета подфракции.

## Дропдауны

CSS `columns` даёт независимые колонки по высоте, но браузер балансирует элементы и может перекидывать карточки между колонками при раскрытии. Это неприятно для стабильного порядка.

Более правильный будущий вариант:

- Делить группы на две явные колонки на уровне Vue.
- Левая колонка рендерит свой массив групп, правая — свой.
- Раскрытие дропдауна в одной колонке не должно менять порядок элементов в другой.

`flex-wrap` и обычный `grid` не решают это полностью, потому что строки остаются общими.

## 3D-модели

## Android

Capacitor подключён, сборка debug/release APK работает локально без Android Studio.

- Toolchain (JDK 21 + Android SDK) вынесен из `~` на SD-карту (`/run/media/deck/EE4S8/android-toolchain/`) — экономия ~950 MB на системном SSD. Пути прописаны в `~/.bashrc`/`~/.zshrc` и `android/local.properties` (гитигнорится).
- Release-сборка подписывается локальным self-signed keystore (`android-toolchain/keystore/release.keystore`, путь/пароли — только в `local.properties`, в git не попадает). Годится для sideload, не для Play Store.
- `npm run android:sync` (build + `cap sync android`), затем `./gradlew assembleDebug` / `assembleRelease` в `android/`.
- Без ADB/USB APK можно передать на телефon/планшет через `python3 -m http.server` в папке с APK и скачать по LAN в браузере устройства.
- Итоговый APK — **~338 MB**, почти целиком это забандленные голосовые линии (см. ниже), не картинки.

### Размер APK — разбивка

Проверено (`du` по `src/interface/data`):

- **Аудио (ogg/oga/wav): ~379 MB, 10 959 файлов.** Это доминирующая часть размера — уже сжатый OGG, дальше сжимать особо некуда без потери качества/деталей реплик.
- Картинки (webp/png/jpg): **~11 MB, 160 файлов** — не проблема, WebP-пайплайн уже отработал.
- Найден мёртвый груз: `factions/professionals/master/audio_wav/` — **55 MB** несжатых WAV, закоммичены в git, не подключены ни в один `audio.ts` (не участвуют в `import.meta.glob`). Кандидат на удаление.
- OGG/OGA уже лучше WAV по размеру; дальнейшее сокращение — это либо понижение битрейта голосовых линий, либо переход на Opus, либо ленивая догрузка аудио вместо бандлинга в APK (актуально, если 338 MB станет проблемой для установки/обновлений).

## UX и безопасность — аудит (2026-07-23)

Прогон агента по `src/pages`, `src/widgets`, `src/router`, `capacitor.config.ts`, `AndroidManifest.xml`, `npm audit`, `scripts/*.mjs`.

### Стоит исправить

1. **Нет error/retry состояния у асинхронных лоадеров.** [SubfractionPage.vue](src/pages/SubfractionPage.vue) и [FactionPage.vue](src/pages/FactionPage.vue) вызывают `loadAudioSource()`/`loadPreviewSource()` без `try/catch` вокруг. Если промис зареджектится — страница зависает в "loading" навсегда, без возможности повторить.
2. **Нет catch-all/404 роута.** В [router/index.ts](src/router/index.ts) нет `:pathMatch(.*)*`. Битая/устаревшая ссылка или deep link с Android даёт пустой `<router-view>` — тупик без выхода, кроме логотипа в хедере.
3. **Одновременное проигрывание нескольких реплик в дропдаунах.** [AudioContent.vue](src/widgets/AudioContent.vue) рендерит по нативному `<audio controls>` на реплику без координации между ними — можно запустить несколько параллельно, они наложатся друг на друга. В [SoundpadContent.vue](src/widgets/SoundpadContent.vue) уже сделано правильно: один переиспользуемый `Audio()`, пауза/сброс перед переключением. Стоит перенести этот паттерн в `AudioContent.vue`.
4. **Нет обработки аппаратной кнопки "Назад" на Android.** В `package.json` нет `@capacitor/app`, соответственно нет `App.addListener('backButton', …)`. В Capacitor WebView без перехвата back either выходит из приложения с любой страницы, либо расходится с историей Vue Router.
5. **Дропдаун в хедере не закрывается по Escape и не управляет фокусом.** [AppHeader.vue](src/widgets/AppHeader.vue) открывает меню только по клику; нет `keydown.esc`, фокус не уводится при открытии/закрытии — неудобно для клавиатурной навигации.

### Проверено, проблем нет

- Нет `v-html`/`innerHTML`/`eval`/`Function()` нигде в `src/` (grep по всему дереву) — инъекций через шаблоны нет в принципе.
- Нет ни одного текстового инпута/формы в проекте — большинство классов XSS/инъекций неприменимы просто потому, что нет поверхности для пользовательского ввода.
- Резолюция аудио-URL (`createSubfractionAudioSource.ts`) — ключи `audioModules` целиком статические, из `import.meta.glob`, резолвятся на этапе сборки; это закрытый словарь, а не динамическая склейка пути, path traversal невозможен даже теоретически.
- `npm audit` — 0 уязвимостей.
- `capacitor.config.ts`: `allowMixedContent: false`, cleartext-трафика нет. `AndroidManifest.xml`: `MainActivity` экспортирован (обязательно для launcher-активности), `FileProvider` корректно `exported=false`. Единственное разрешение — `INTERNET`, теоретически можно убрать (весь контент бандлится офлайн), но угрозы не несёт.
- `scripts/scrape-agents.mjs` дергает внешний сайт и пишет через `JSON.stringify` (без риска инъекции кода), но это ручной dev-скрипт, не встроен в CI/сборку — риск чисто теоретический.
- `scripts/compress-images.mjs` работает только с локальными файлами через `sharp`/`fs`, без shell-вызовов и сети — рисков нет.

## Небольшие оптимизационные хвосты

Это не блокеры, но к ним можно вернуться позже.

- В dev-режиме Vite всё ещё обрабатывает много аудиофайлов. Production preview быстрый, но старт dev-сервера может оставаться тяжёлым.
- В `SubfractionPage.vue` всё ещё широкий glob по картинкам: `/src/interface/data/**/*.{png,jpg,jpeg,webp}`. Картинок мало, поэтому это не критично, но позже можно сузить.
- В каждой подфракции есть локальный `import.meta.glob` по трём форматам: `wav`, `ogg`, `oga`. Если проект окончательно перейдёт только на `ogg/oga`, `wav` можно убрать.
- `audio.ts` сейчас создаёт `audioSource` при импорте модуля. Это уже лениво относительно страницы, но внутри самой подфракции source создаётся целиком. Позже можно грузить/строить только выбранную страницу.
- `buildVoicePages` выполняет семантическую группировку на клиенте. Если понадобится ещё ускорить первый вход в подфракцию, можно генерировать manifest заранее.
- `AudioContent` держит resolved items в локальном состоянии компонента. При смене страниц и подфракций это нормально, но позже можно подумать о более явном cache-сервисе.
- `vite-plugin-vue-devtools` полезен в разработке, но добавляет dev-накладные расходы. Для замеров производительности лучше использовать `build + preview`.
- Production build может падать на `EPERM` при записи файлов в `dist/assets`, если `preview`, браузер, антивирус или индексатор держит старый ассет. Это не ошибка архитектуры.

## Будущие идеи

### 1. Несколько фоновых видео в случайном порядке

Сейчас на главной одно фиксированное видео. Хочется набор коротких роликов, проигрываемых в случайном порядке.

- Реализация: массив URL (или `import.meta.glob` по `public`/`data`), `pickRandom`, смена `<source>`/`src` по событию `ended` (для loop'а одного — убрать `loop`, слушать `ended` и грузить следующий).
- Вопрос по ресурсам: **N коротких роликов при тех же суммарных характеристиках (битрейт/разрешение/длительность) почти не дороже одного длинного по трафику** — суммарный вес примерно равен. Различия: (а) больше HTTP-запросов и накладных на контейнер/заголовки каждого файла (мелочь); (б) микро-паузы/буферизация на стыках — лечится предзагрузкой следующего ролика (второй скрытый `<video>` с `preload="auto"`); (в) декодер чаще переинициализируется. По CPU/decode при одинаковом кодеке разница незначительна. Вывод: дешевле всего — короткие ролики одного кодека/разрешения + префетч следующего.

### 2. Парсинг текстовой информации об остальных агентах

Цель: добить недостающих агентов в `src/interface/data/agents/` (текст + по возможности картинки, иначе плейсхолдер), не копируя вручную.

- Подход: одноразовый Node-скрипт (`scripts/`), который тянет страницы (steamcommunity.com / csgoskins.gg), парсит имя/описание/редкость через `cheerio`, складывает в `Agent`-консты и качает изображения (прогоняя через тот же `compress-images`). Где картинки недоступны — оставлять текущий плейсхолдер (`agents/default/...`).
- Нюансы: уважать `robots.txt`/ToS, ставить задержки между запросами (не долбить), кэшировать html локально. Тексты/арт принадлежат Valve — для фанатского/учебного проекта обычно ок, но стоит держать атрибуцию и не выдавать за своё.
- Альтернатива копированию вручную: поискать готовые датасеты (CS2 agents dump на GitHub / Steam API), что чище, чем скрейп вёрстки.
